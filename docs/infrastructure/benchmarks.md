#### トークン比較検証（Yes/No vs 1/0）
* **`Yes/No`**: 正解率 **91.7%**, ニアミス遮断率 **100.0%**, 正例・ニアミス平均マージン差 **$\Delta z_{\text{diff}} = 5.32$** (正例: +1.14 / ニアミス: -4.18)
* **`1/0`**: 正解率 **45.4%**, ニアミス遮断率 **5.6%**, 正例・ニアミス平均マージン差 **$\Delta z_{\text{diff}} = 2.87$** (正例: +4.49 / ニアミス: +1.62)
* **結論**: $N=108$ へのデータセット倍増後も、`1/0` は数字特有の頻度バイアスでニアミスを 94.4% 誤爆通過させるのに対し、`Yes/No` は対話アライメントと完全一致し、**ニアミスを 100% 遮断できる堅牢性**を明確に実証。

#### ASCII Matcher ($\beta$) 感度分析 ($\tau=0.55$)
* **$\beta=0.0$ (ブーストなし)**: Accuracy 87.0%, F1 75.9%
* **$\beta=1.2$ (推奨設定)**: Accuracy **91.7%** (+4.7pt), F1 **85.7%** (+9.8pt)
* **所見**: 英数記号識別子（エラーコード、コマンド、型番、条文番号等）の部分一致ブーストにより、偽陰性を大幅に削減しながらも、ニアミス遮断率 100.0% を維持。

## 8. 将来の性能改善ロードマップ (Take Note)

現行アーキテクチャで達成したプロダクション基準（堅牢なセマフォ制御、マルチAPIキー認証、OpenAPI完全準拠、全テスト100%成功、Logit Gate ハイブリッドリランキング統合）を維持しつつ、さらなるスループット向上とエコシステム拡張に向けた改善検討項目です。

1. **インメモリ LRU / TTL キャッシュ層**:
   - 頻出検索クエリや同一文書のハッシュ（SHA-256）に基づくベクトル埋め込み結果のインメモリ（または Redis）キャッシュ。同一クエリ時の推論オーバーヘッドを完全ゼロ化（< 1ms 返却）。
2. **ダイナミック・リクエストバッチング (Dynamic Request Batching)**:
   - 短時間（例: 5〜20ms）に到着した複数の個別リクエストを自動で1つのテンソルバッチに束ねて推論（`model.forward`）を実行。CPU/GPUの並列演算能力を最大化し、高アクセス時のスループットを 3〜5 倍向上。
3. **Helm Chart パッケージング (`deploy/helm/`)**:
   - Kubernetes マニフェストに加え、ConfigMap / Secret / Ingress / HPA / Autoscaler を一括管理できる公式 Helm Chart の整備。
4. **ハイブリッド検索エンドポイント (Hybrid Search: Sparse + Dense)**:
   - 既存の Dense ベクトル埋め込み・リランキングに加え、BGE-M3 の Lexical Weights や BM25（Sparse）の統合スコアリングエンドポイントの提供。
